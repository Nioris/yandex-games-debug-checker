# Yandex Games requirements re-audit — 2026-09-01

This note records how the public checker was adjusted after the August 2026 Yandex Games documentation updates. The checker is unofficial; the linked Yandex documentation remains the source of truth.

## Official changes relevant to the embedded checker

- **1.2 / 1.2.1 Authorization** — only Yandex ID authorization is allowed; the authorization dialog must follow a deliberate user action; the offer must explain benefits; the game must remain usable without authorization.
- **1.3 Focus/audio** — game sound stops on focus loss. The moderation method covers minimize, another tab and the browser tab switcher; a delay up to two seconds is allowed, with documented platform exceptions.
- **1.6.2.4 Keyboard layout** — desktop controls must not depend on the active keyboard layout.
- **1.9 Progress** — mobile progress must not be lost when device orientation changes.
- **1.10 Display** — the game must remain correctly displayed on window resize and screen rotation.
- **1.12 Monetization** — ads or in-app purchases are expected unless the developer explicitly states in the Draft developer comment that monetization is intentionally disabled. The startup ad does not count.
- **1.15 Finished state** — all required texts, graphics, controls and gameplay mechanics must be complete.
- **4.4 Ad placement/testing** — Yandex documents real-ad testing in prod and draft and a 0.33s maximum delay for applicable user-action placements.

## Checker policy changes

The update deliberately avoids turning weak static signals into hard failures.

- Third-party authorization markers produce **WARN**, not FAIL.
- Authorization benefit text and guest-play availability become **NOT VERIFIED** when auth is present because static source scanning cannot reliably judge the visible flow.
- The 1.3 static signal now requires both a focus-loss hook and an audio stop/mute pattern to PASS.
- Layout-dependent `KeyboardEvent.key` letter controls are now tied to **REQ 1.6.2.4**.
- Orientation progress under 1.9 is explicitly **NOT VERIFIED** and moved to the manual checklist.
- Canvas/WebGL resize/orientation handling is mapped to the current **REQ 1.10** wording.
- Lack of ads/IAP is **NOT VERIFIED**, not FAIL, because an explicit no-monetization developer comment is valid under 1.12.
- The WIP scan under 1.15 only flags obvious placeholders; a clean scan is still **NOT VERIFIED** for overall completeness.
- REQ 4.4 now measures `callbacks.onOpen` timing when observable instead of treating the SDK method-call timestamp as proof of actual ad start.

## Console-only August changes

Promo scheduling, promo text limits, the CSP tab rename, Draft archive/orientation/title/screenshot field changes, mandatory horizontal video, contract/ULM workflow and payout thresholds are not browser-runtime requirements. They belong in the manual/pre-submit Console checklist rather than being reported as embedded-checker PASS/FAIL.
