# Public-release audit — 2026-08-11

Scope: convert the supplied internal Debug Checker v2.22 into a public, side-effect-minimized repository suitable for other Yandex Games developers.

## Source audit findings and changes

### Removed internal-only assumptions

- `var _lang` must be global.
- a function named `setLang()` must exist.
- a function named `t()` must be used a minimum number of times.
- a fixed set of 13 languages must exist.
- language-switch UI cache conventions tied to internal tooling.
- activation by a project-specific `#game-version` element.
- internal `.pre-submit-report.json` integration.
- leaderboard write/read tooling that could modify test data.

### Corrected against current official documentation

- Game Ready hard limit changed from an internal 10-second heuristic to the documented 90-second moderation window.
- The blanket assumption that `localStorage.setItem` is wrong was removed. Current guidance allows browser storage for simple non-IAP games; cloud storage is required for IAP and recommended for broader continuity.
- The fixed 13-language requirement was removed. Moderation checks the languages declared in the draft; platform-supported languages are broader than the old internal list.
- IAP currency references were updated away from deprecated requirement 3.8 to current 1.13.2 wording.
- Presence checks for `GameplayAPI.start/stop` were removed because gameplay markup is optional; correctness matters if it is used.
- Presence checks for `game_api_pause/resume` were removed because those events are optional; correctness matters if the associated API is used.
- Interstitial "must follow a user gesture" was changed from universal FAIL to contextual WARN. Current 4.4 rules also allow timer-based placement in long real-time gameplay. The 0.33-second limit remains relevant to user-action placements.
- Rewarded-video calls with no recorded user gesture can still hard-fail; delayed calls after a gesture are WARN because the checker cannot fully infer UI semantics.

### Verdict safety policy

Most pattern-based failures are downgraded to WARN unless the check is in a small audited hard-fail allow-list. Since v1.1.0, lack of evidence is separated again into NOT VERIFIED: WARN means an observed risk signal, while NOT VERIFIED means the checker could not prove the result automatically. This prevents uncertainty or coding-style assumptions from being presented as authoritative platform violations.

## Side-effect audit

- No telemetry or analytics added.
- No external source upload.
- No leaderboard score writes.
- No purchases or save mutation.
- Static source fetches are same-origin/relative only.
- SDK instrumentation wraps and delegates to original methods.

## Functional validation

The repository includes:

- JavaScript syntax validation with `node --check`;
- static regression tests against the actual check definitions extracted from `debugcheck.js`;
- catalog parity test (`checks.csv` vs executable checks);
- public-hygiene audit for removed internal identifiers and mutation tooling;
- headless Chromium smoke test using a local fake Yandex SDK to verify load order, SDK interception, public API and panel rendering.

Run `npm run audit` to repeat the full local validation.

## Addendum: Orc Castle public example

A real Canvas game was added as an executable before/after fixture under `examples/orc-castle/`.

Chromium audit result:

- before: 45 PASS / 3 FAIL / 12 WARN / 10 NOT VERIFIED (75% score);
- after: 70 PASS / 0 FAIL / 0 WARN / 2 NOT VERIFIED (100% score, 97% automated coverage).

The after fixture verifies SDK bootstrap, startup I18N access, Game Ready capture, input gating, context-menu protection, canvas sizing, optional GameplayAPI start/stop lifecycle, and continued game execution in a real browser DOM.

During this audit three checker-policy issues were corrected as well:

1. Ad pause checks no longer warn/fail games that do not use fullscreen ads.
2. Runtime ad-context checks become N/A when no ads were observed, and the interstitial rule now acknowledges that long real-time levels may use timer-based ads under the conditions described in requirement 4.4.
3. A raw document input event before Game Ready is now advisory rather than labelled as proof that the game accepted input; the game still needs an explicit input gate.

The production `after/index.html` contains no mock SDK. `index.mock.html` and `mock-sdk.js` exist only for GitHub Pages / browser test execution.


### v1.1.0 localization/result-state addendum

The checker now separates **NOT VERIFIED** from **WARN**. Missing runtime evidence is no longer presented as a defect signal. `environment.i18n.lang` is instrumented before the SDK object reaches game code when `YaGames.init()` is intercepted, so actual language access can be proven at runtime. The fallback checker can execute an optional `YGDebugCheckerConfig.resolveLanguage` resolver or infer common explicit mappings; if neither is possible, the result is NOT VERIFIED rather than WARN. The Orc Castle `after` fixture proves all three localization checks automatically: SDK language read, `be/kk/uk/uz → ru` fallback, and language-read-before-Game-Ready ordering.
